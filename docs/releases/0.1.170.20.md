# ModelPort 0.1.170.20

## 指令审核决策链路

- 指令审核按“用户白名单、全局风险库、可信哈希、AI 审核”的固定优先级处理受审核的 Responses 请求；只选择非空 `instructions`，否则回退到非空 `input[1]`，模型不参与审核范围判断。
- AI 节点固定为一个同步初筛槽位 `sync` 和三个并行异步复核槽位 `async_1`、`async_2`、`async_3`。同步通过时当前请求立即放行并创建持久化复核任务；同步拒绝时立即拦截并写入全局风险库。
- 同步结果为不确定、超时、异常或格式无效时，当前请求保持拦截并创建可重试复核任务。异步复核取得两票通过后写入全局可信库，取得两票拒绝后写入全局风险库；无多数结论时按配置的退避间隔持久化重试。
- 观察模式始终放行并保留事件及复核记录，但任何 AI 结果都不会写入可信库或风险库。拦截响应继续使用通用 `403 request_rejected`，并保留“疑似破限，如有误判，请联系本站管理员”的中文提示。

## 证据与管理能力

- 新增独立的加密内容库、全局风险库、复核任务、异步尝试、租约和重试状态；AI 结论、提示词版本、模型、置信度、原因、字段来源和关联事件均可追溯。
- 管理后台扩展为审核日志、可信哈希库、风险拦截库、复核任务、审核范围和 AI 设置六个工作区，支持风险条目人工确认、转入可信库、禁用、删除，以及失败任务人工重试。
- 原文查看和复制继续按需解密并记录敏感访问审计；普通应用日志和管理操作请求体不记录原文、Bearer Token 或 AI API Key。指令审核模块移除 TOTP/step-up 门槛，但保留正常管理员身份认证和权限校验。
- 运维通知仅发送给已配置的运维接收方，不向下游用户发送邮件；观察放行、哈希放行、AI 放行、风险拦截和待复核状态分别统计。

## 数据与兼容性

- 新增迁移 `219_instruction_audit_v2_review_pipeline.sql`，数据库迁移总数从 271 增至 272；迁移可重复执行，并兼容已有 V2 可信哈希、候选记录、事件和 AI 节点配置。
- 修复 PostgreSQL `INT[]` 异步重试计划的读取和写入类型转换，配置加载不再因数组扫描失败进入降级状态。
- 本次迁移不修改用户、余额、API Key、账号、分组、订阅、用量或计费数据；新能力默认保持关闭，管理员完成范围和 AI 节点配置后再选择观察或拦截模式。
