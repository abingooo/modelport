# ModelPort 0.1.170.7

## 指令审核

- 在安全审计中原生新增“指令审核”，覆盖下游 OpenAI Responses HTTP 请求和 WebSocket 的每个 `response.create`，显式 compact 端点保持排除。
- 仅对管理员绑定的“下游用户 + 原始模型名”生效，依次检查顶层 `instructions` 和回退字段 `input[1]`；两个来源共享同一个 SHA-256 哈希池，任一命中即可放行。
- 系统设置的安全设置中新增总开关，迁移后默认关闭；多实例通过 PostgreSQL 配置版本、Redis 失效通知和定时刷新同步，无需重启。
- 管理员可维护哈希库、候选哈希、规则集、下游绑定和拦截日志；支持手动摘要、浏览器本地原文计算、有效时间窗口和新旧客户端摘要并存。

## 拦截与通知

- 未通过审核的请求在选号、上游转发和计费前返回通用 HTTP 403，不向下游暴露字段名称、摘要或白名单规则。
- 拦截事件和邮件 outbox 在同一个 PostgreSQL 事务中持久化，不保存请求正文、Bearer Token 或 API Key；SMTP 发送继续由后台任务异步执行。
- 邮件通知按用户、模型、原因和 15 分钟窗口去重，并记录已成功通知的管理员；部分失败重试时不会重复发送给已成功收件人。

## 安全与兼容

- 使用严格 JSON 解析并拒绝重复键、非法 UTF-8、非法 JSON、超限字段和过度复杂请求；指令审核请求体上限为 16 MiB，单个被审核文本上限为 1 MiB。
- 只有明确的 HTTP `/responses/compact` 路径排除审核；普通 `/responses` 中的 `compaction_trigger` 和客户端声明的 beta header 均不能跳过审核，WebSocket 每轮同样执行审核。
- 配置快照使用只读 `REPEATABLE READ` 事务加载，刷新串行化并拒绝版本回退；刷新故障期间保持最后有效的开关与绑定范围，连续失败 30 秒后对已绑定请求 fail-close，摘要有效期仍在每次匹配时实时判断。
- 新增数据库迁移 `198_instruction_audit.sql`，不修改现有用户、API Key、分组、账户、余额、订阅或历史用量数据。

## 验证与部署

- 已覆盖默认关闭、未绑定放行、两级匹配、统一哈希池、严格 JSON、模型规范化、有效期、事件与 outbox、HTTP/WS 路由、通用 403 和 47 KB 延迟预算；前端完整测试共 1567 项通过。
- 正式镜像仅发布 `linux/amd64`，标签为 `ghcr.io/abingooo/modelport:custom-v0.1.170.7`。
- 发布工作流只创建 GitHub Release 和 GHCR 镜像，不自动更新测试服务器或生产服务器；本版本只部署到测试服务器进行验收。
