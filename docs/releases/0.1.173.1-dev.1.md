# ModelPort 0.1.173.1-dev.1

> 本版本为开发预览版，基于 Sub2API `v0.1.173`，合并上游 `v0.1.171` 至 `v0.1.173` 的更新，并保留 ModelPort 现有产品语义。开发版发布不等于测试服或生产环境已部署。

## 主要更新

### 认证与安全

- 修复 pending OAuth exchange 可能导致账号错误绑定的问题，并加强 OAuth 状态的一次性消费与凭据隔离。
- 修复多页面并发刷新令牌时的轮换竞态。
- 接入腾讯和阿里云验证码门禁，补充邮箱域名注册额度控制。
- 加强账号凭据脱敏、Codex 客户端身份与版本同步逻辑。
- 为直连、TLS 和代理上游请求增加明确的连接超时，缩短故障转移等待时间。

### 支付、订阅与计费

- 退款余额不足时要求显式强制确认，并增强并发余额扣减和 Stripe 退款幂等性。
- 修复并发续期可能丢失订阅天数、日额度未按配置时区午夜重置的问题。
- 金额统一量化到数据库 `NUMERIC(20,8)` 精度；计费失败时仍保留未结算用量记录。
- 增加上游实际响应模型及模型不匹配观测。
- 完善 Grok 搜索、Voice、视频的显式定价门禁和计费，异步视频仅在 `done` 且存在 `video.url` 后结算。

### 网关与模型兼容

- 加强 OpenAI Responses、Chat Completions、Messages 和 WebSocket 的故障转移、路由提示、工具 Schema 清洗及终态事件处理。
- 非流式图片请求在客户端断开后继续完成上游结算，避免上游已出图但漏计费。
- 支持 Gemini 3.6 Flash，并按上游实际返回图片数计费；池模式 429 不再错误扩大为账号级限流。
- 完善 Grok OAuth/SSO、模型映射、免费额度门禁、账号冷却、视频、Web Search、TTS、STT、Realtime 和 Custom Voice 网关能力。
- 不恢复已经退役的 BatchImage 产品路由和界面。

### Channel Monitor V2

- 新增基于真实网关流量的被动监控、分层聚合、趋势、回填、隐私控制及管理员配置。
- 默认继续使用 V1，V2 可按设置启用。
- 保留 ModelPort 国内渠道监控，并将 DeepSeek、Qwen、GLM、Kimi、Doubao、MiniMax 和 MiMo 纳入 V2 工厂配置；默认刷新周期为 5 分钟。

### ModelPort 定制保留

- 保留指令审核 V2：支持禁用 `other`、`unknown`，分组可多选客户端类型，筛选后全选并批量删除日志。
- 保留 AI 端点超时后的字段复审续跑、可信哈希原文和来源账号关联。
- 保留 DashScope OpenAI-compatible 审核适配，包括 `qwen3.5-plus`、`qwen3.6-plus` 和 `qwen3.7-plus`。
- 审核仍在网关路由分发前执行，不恢复已删除的旧审核路径。
- 模型广场官方基础价继续取渠道原始定价；重复模型按渠道创建时间最早、再按渠道 ID 选择。分组倍率、峰时倍率和用户倍率仅用于计算用户实际价，不回退 LiteLLM 官方价。
- 保留图片档位实收价、Composite 模型展开、CNY 展示、免费分组、利润控制、国内 OpenAI-compatible provider 和 ModelPort 发布规则。

## 数据库升级

- 本候选共包含 **294 个 SQL migration 文件**，迁移身份由完整文件名确定。
- 相同数字前缀不代表重复迁移，尤其两个 `220_*` 文件职责不同，均不得删除、重命名、合并或跳过。
- `220_clear_non_grok_video_generation_config.sql` 会先备份非 Grok、非 Composite 分组的既有视频价格，再清空对应在线字段。
- `222_restore_modelport_non_grok_video_prices.sql` 是 ModelPort 的配套恢复迁移，仅在在线字段仍全部为空时恢复备份，避免覆盖升级期间的管理员修改。
- `220/222` 是完整的非 Grok 视频价格备份与恢复流程，不应被误解为 Grok 视频功能迁移。`groups_video_price_backup_220` 应保留至升级备份保留期结束。
- 升级前必须备份 PostgreSQL，并在生产快照副本上验证迁移可重复执行、checksum、数据行数和恢复流程。

## Voice 与 Redis 运维要求

- Grok Custom Voice 的用户、资源和 xAI 上游账号归属绑定存储在 Redis。启用 Voice 前必须开启 Redis 持久化，并将 Redis 数据纳入备份、恢复和灾备流程；仅备份 PostgreSQL 不足以恢复 Voice 归属。
- Redis 数据丢失后，Voice ownership 会 **fail-closed**：系统拒绝访问无法证明归属的旧资源，不会把它们重新调度到其他账号。丢失的旧绑定无法从 xAI 自动重建，相关旧 Voice 资源在 ModelPort 中不可恢复。
- 删除并重新创建同一 xAI Team 账号会产生新的本地 account ID，旧绑定不会自动迁移；存在 Voice 资源的账号不得通过删除重建方式轮换。
- 当前明确不支持 `call_id` 恢复和 SIP 呼叫。携带非空 `call_id` 的 HTTP 或 WebSocket 请求会返回 `400`，该参数不会转发给 xAI。
- Voice HTTP 请求在客户端断开后仍会完成必要的上游处理和计费，但受独立总时限约束；默认 300 秒，可配置范围为 1 至 540 秒。上游响应体停滞达到时限后会关闭响应体并释放连接及并发槽。
- Custom Voice 创建采用 Redis 原子 reservation，reservation 有效期为 **10 分钟**。在上游已创建成功、但本地 ownership commit 及随后 readback 同时遭遇极端 Redis 故障时，系统可能无法确认创建结果：客户端收到 `503`，响应不会暴露 `voice_id`，上游可能遗留无法在本地关联的资源，reservation 会保留至 10 分钟 TTL 到期。
- Realtime `conversation_id` 的账号绑定有效期为 24 小时；Redis 不可用或归属缺失时同样拒绝恢复。
