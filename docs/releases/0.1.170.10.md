# ModelPort 0.1.170.10

## 指令审核客户端范围

- 指令审核的“分组与规则集绑定”新增客户端范围。选择指定客户端后，请求必须同时命中下游认证分组和客户端类型才进入审核；选择“全部客户端”时保持原有按分组审核的行为。
- 支持同时选择多个客户端，并识别 Codex VS Code、Codex CLI、Codex Desktop、OpenCode、可信 ModelPort 内部调用、其他客户端和未知客户端。同一请求命中多条绑定时会合并对应规则集与哈希池。
- 旧绑定升级后自动使用“全部客户端”，旧版 API 在更新绑定时省略 `client_types` 也会保留已有客户端范围，不会因升级意外缩小或改变既有审核覆盖面。

## 识别与安全边界

- Codex 与 OpenCode 客户端按约定的 User-Agent 前缀进行大小写不敏感匹配；UA 存在但未命中规则时归类为“其他客户端”，UA 缺失或无法解析时归类为“未知客户端”。
- User-Agent 只用于审核范围分类，可由下游调用方伪造，不能作为身份认证或安全边界。`modelport_internal` 仅接受服务端可信上下文标记，伪造 User-Agent 不会获得内部调用身份。
- HTTP Responses 请求与 WebSocket 的首轮、后续轮次使用同一客户端识别信号并逐次审核；`/responses/compact` 继续沿用现有排除策略。

## 日志与人工审查

- 被拦截记录新增客户端类型与最多 512 字节的 User-Agent 快照，审核日志支持按客户端筛选，也可通过统一搜索检索客户端类型和 User-Agent。
- 审核列表、证据详情和一键复制审查包均展示客户端元数据；指令审核运维通知新增客户端类型，用户通知仍不暴露审计实现细节或请求原文。
- 历史审核记录保留不变，并以“未知客户端”和空 User-Agent 兼容展示。

## 数据与发布

- 新增迁移 `201_instruction_audit_client_scope.sql`，仅为分组绑定和审核事件增加客户端范围及索引。迁移可重复执行，不修改用户、API Key、余额、订阅、用量、哈希库、规则集或既有拦截证据。
- 正式镜像仅发布 `linux/amd64`，标签为 `ghcr.io/abingooo/modelport:custom-v0.1.170.10`；发布工作流只创建 GitHub Release 和 GHCR 镜像，不自动部署生产环境。
