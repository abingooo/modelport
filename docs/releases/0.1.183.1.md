# ModelPort 0.1.183.1

ModelPort `0.1.183.1` 基于 Sub2API `v0.1.183` 重建，上游基线提交为 `e8cb019fabf8b55199436229044cbf9aa7a82564`。本次重建保留 ModelPort 的产品差异，同时继续继承上游网关、计费、渠道与协议能力。

## 主要内容

- 完整恢复 ModelPort 品牌体系、双版本显示和动态模型港首页。
- 保留免费分组及其订阅、计费和迁移兼容逻辑。
- 保留即时抽奖、定时开奖、管理配置、幂等结算和用户记录。
- 在新上游基线上恢复指令审核 V2 的采集、判定、复核、统计、可信项和敏感访问能力。
- 恢复用户侧 API 密钥连通性测试，并保持服务端代理和权限边界。
- 将版本发现切换到 `abingooo/modelport` 的四段稳定版本通道。
- 新增不可变 GHCR 镜像、SBOM、provenance、Cosign 签名、Release 校验和与 digest 固定的宿主更新协议。

## 兼容性

- 支持从旧 ModelPort `custom-v0.1.176.2` 数据库升级，也支持 Sub2API `v0.1.183` 数据库和空数据库初始化。
- 旧 ModelPort 独有迁移仅用于历史 checksum 兼容；新的终态迁移不会重放或重写旧迁移。
- 用户、余额、订单、订阅、API Key、账号、渠道、用量、抽奖和审核数据不得被删除或静默改名。
- 指令审核继续使用现有 `TOTP_ENCRYPTION_KEY`、32 字节根密钥、HMAC-SHA256 purpose 派生和 AES-256-GCM。指令证据保持原有 evidence 派生路径；哈希原文与 V2 content vault 继续共用原有 hash-raw 派生路径。purpose、AAD、`nonce || ciphertext || tag` 布局、编码、版本标识、可用性判断、失败语义和敏感访问授权流程均不改变。
- 本版本不新增密钥版本分派、历史别名或解密回退路径；本次迁移和上游兼容适配不得为兼容目的轮换密钥、调整算法或参数、批量解密或重加密，也不得新增密文迁移、读时改写、写时转换或版本字段清洗。本次迁移和上游兼容适配不得改写数据库中已经存储的密文字节或 SHA-256 摘要；旧 ModelPort 原有的到期清理以及显式业务操作产生的正常密文写入和更新行为保持不变。V2 content vault 现有版本字段命名与实际 hash-raw 派生路径之间的历史差异继续原样兼容。

## 发布标识

- Git 标签：`custom-v0.1.183.1`
- 镜像：`ghcr.io/abingooo/modelport:custom-v0.1.183.1`
- 提交镜像标签：`ghcr.io/abingooo/modelport:sha-<40位发布提交>`
- 支持平台：`linux/amd64`

镜像的最终 `sha256` manifest digest、发布提交、上游提交和五个 digest 固定的基础镜像以本 Release 的 `manifest-digest.txt`、`release-revision.txt` 与 `release-metadata.json` 为准。宿主更新器还会要求 OCI revision 标签与 `release-revision.txt` 完全一致。正式运行时应使用 digest 固定引用；本版本不发布或依赖 `latest`、主版本、主次版本等可变标签。

## 更新边界

此 Release 的发布不会连接、更新、重启或回退任何生产实例。GitHub/GHCR 的公开验证完成后，发布流程即停止；生产更新由管理员完成备份与环境核对后，在 ModelPort 站内手动发起。

宿主更新器、systemd 单元和 ModelPort Compose override 作为校验和覆盖的 Release 资产提供，但不会随容器镜像自动安装或替换。override 让 `/app/data/update-request` 与宿主部署目录中的 `data/update-request` 指向同一绑定目录，并继续让在线更新默认为 `manual`。新镜像默认以 `sub2api` 非 root 用户（UID/GID `1000:1000`）运行；首次使用绑定目录时必须由运维人员预先确认该目录及其文件可由 `1000:1000` 写入。已有旧版目录通常已由旧 entrypoint 完成属主修复；如确需一次性修复，可在维护窗口显式以 root 启动后再恢复默认用户。首次从旧版更新时继续兼容一行四段版本请求；是否安装新的 digest 固定更新器必须由运维人员另行确认。
