# ModelPort 0.1.170.16

## Cyber Policy 完整请求证据

- 上游触发 `cyber_policy` 后，内容审核日志会保存客户端提交的完整下游 JSON 请求体，不再受原有 4096 字符上游错误摘要限制。
- 保存内容取自协议转换、模型映射、推理参数策略和其他字段改写之前；覆盖 Responses HTTP、Chat Completions、Anthropic Messages 兼容入口及 Responses WebSocket 的每个 `response.create` turn。
- HTTP 压缩请求保存解压后的原始 JSON 字节；正文不裁剪、不格式化、不重排字段，SHA-256 与加密原文基于同一份字节计算。
- 只保存请求体，不保存 `Authorization`、Cookie 或其他请求头。完整正文不会进入邮件、普通应用日志、运维错误日志或内容审核分页列表。

## 管理员查看

- 内容审核列表为 Cyber Policy 记录展示“查看完整下游 JSON”、正文大小和 SHA-256 元数据；正文仅在管理员打开详情时按需解密。
- 详情保留原始文本展示，支持一键复制完整 JSON 和 SHA-256；响应设置 `Cache-Control: no-store`，不要求额外 TOTP 或敏感内容授权。
- 升级前的历史 Cyber Policy 日志没有原始正文，界面会明确显示“原始 JSON 不可用”，原有日志内容不受影响。

## 数据与安全

- 新增迁移 `218_content_moderation_cyber_evidence.sql`，以日志 ID 建立独立证据表；正文复用现有 AES-256-GCM 敏感数据密钥加密，日志删除或到期清理时证据通过外键级联删除。
- 加密失败时不会降级保存明文；证据写入失败时保留通用失败状态的 Cyber Policy 审核记录，便于管理员追踪。
- 迁移可重复执行，数据库迁移总数从 270 增至 271；不修改用户、余额、API Key、账号、分组、订阅、用量或计费数据。

## 验证与发布

- 已覆盖完整长正文、原始字节 SHA-256、加密失败、事务写入、按需解密、异步正文快照、请求头隔离、管理员查看和复制测试。
- 正式版本仅构建 `linux/amd64`，发布为 `ghcr.io/abingooo/modelport:custom-v0.1.170.16`。
