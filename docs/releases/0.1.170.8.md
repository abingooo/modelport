# ModelPort 0.1.170.8

## 分组审核范围

- 指令审核改为按认证阶段确定的下游 API Key 分组生效，不再使用用户或模型决定审核范围；用户、API Key 和模型继续作为审计元数据记录。
- 管理员可将一个规则集批量关联到多个分组，也可为同一分组关联多个规则集；同一分组关联规则中的当前有效哈希合并为统一白名单，任一摘要命中即可放行。
- 未关联的分组跳过指令审核；已纳入审核的分组在关联规则全部停用、失效或不存在当前有效哈希时默认拒绝，避免配置失效后静默放行。

## 管理与安全

- 指令审核页新增可搜索的多分组选择、关联启停、失效状态提示和分组审计信息；总开关移动至“系统设置 → 功能开关 → 风控中心”。
- 开启总开关前必须至少存在一个启用的分组关联，其规则集包含当前有效的活动哈希，不提供绕过确认；配置仍通过版本刷新和 Redis 通知同步到多实例。
- 继续覆盖 Responses HTTP 与 WebSocket 请求，并保持 `/responses/compact` 排除；请求未通过时仍在上游转发及计费前返回不暴露审核字段的通用 403。
- 分组已纳入审核但规则全部失效时，拦截事件会将空规则集记录为 JSON 数组，确保默认拒绝场景的审计日志和异步通知任务可靠落库。

## 数据与发布

- 新增迁移 `199_instruction_audit_group_scope.sql`，只增加分组关联表及审计事件分组快照字段；原有用户/模型绑定表和历史事件完整保留，不修改用户、API Key、余额、订阅或用量数据。
- 旧用户/模型绑定不再参与运行判定，也不再通过管理 API 和前端暴露；升级后总开关在尚未配置分组关联时保持关闭。
- 正式镜像仅发布 `linux/amd64`，标签为 `ghcr.io/abingooo/modelport:custom-v0.1.170.8`；发布工作流只创建 GitHub Release 和 GHCR 镜像，不自动部署生产环境。
