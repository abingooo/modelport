# ModelPort 0.1.170.9

## 人工审查与证据保护

- 指令审核现在会分别保留被拦截请求中实际参与校验的 `instructions` 和 `input[1]` 原文、SHA-256、字节数及摘要复算结果，供管理员人工确认；不会保存完整请求体、Bearer Token 或其他认证信息。
- 原文使用固定 `TOTP_ENCRYPTION_KEY` 派生的独立 AES-256-GCM 子密钥加密后落库，默认保留 30 天并支持管理员调整。未配置固定密钥时继续执行拦截和摘要审计，但拒绝降级保存明文。
- 审核日志新增证据详情、摘要一致性检查、人工确认和一键复制。查看原文及复制原文、摘要、请求 ID、审查包都会记录管理员、时间、来源、IP 和 User-Agent；候选哈希必须由已完成证据查看的管理员确认后创建。
- 升级前的历史拦截记录保持完整并标记为“历史记录无原文”，不会伪造或补写旧请求内容。

## 日志筛选与状态表达

- 审核日志支持统一搜索请求 ID、用户邮箱、用户 ID、API Key ID 和模型，并支持时间范围、分组、拒绝原因、两个字段的校验结果、用户通知状态和运维通知状态多选筛选。
- 筛选条件会显示为可单独移除的标签并同步到页面 URL；表格中的请求、用户、分组、模型、校验结果、原因和通知状态均可点击反向筛选。
- 校验文案统一为“命中放行规则”“未命中放行规则”“字段缺失”“字段格式无效”和“两项均未命中放行规则”，通知状态区分待发送、发送中、重试、已发送、发送失败、重复通知已抑制及无收件人。

## 安全通知

- 指令审核拦截会分别向下游用户和运维人员写入持久化异步通知任务。用户邮件只说明疑似绕过安全限制及申诉方式；运维邮件只包含请求 ID、用户、API Key、分组、模型和时间，不包含拦截原文。
- 运维收件人优先使用“运维监控”告警邮箱；未配置时回退到首个有效管理员邮箱。相同用户和分组的通知按 15 分钟窗口抑制重复发送，单个任务最多重试 8 次，邮件故障不影响请求拦截结果。
- 上游返回精确 `cyber_policy` 错误码时同样进入用户和运维双通道通知队列，邮件不再携带上游原始错误正文。

## 数据与发布

- 新增迁移 `200_instruction_audit_review_notifications.sql`，只增加加密证据、证据访问日志、通用安全通知队列及审核筛选索引；旧通知状态会迁移为历史只读状态，不重复发送。
- 迁移可重复执行，不修改用户、API Key、余额、订阅、用量、分组或既有指令审核规则。正式部署前必须确认 `TOTP_ENCRYPTION_KEY` 是固定的 64 位十六进制值并完成数据库备份。
- 正式镜像仅发布 `linux/amd64`，标签为 `ghcr.io/abingooo/modelport:custom-v0.1.170.9`；发布工作流只创建 GitHub Release 和 GHCR 镜像，不自动部署生产环境。
