# ModelPort 0.1.170.13

## 指令审核结果与原因策略

- 指令审核统一记录 `blocked`、策略放行、AI 放行、哈希放行和例外放行五种最终结果，并保存初始原因、最终原因、策略动作、请求字节数、审核延迟和 AI 延迟。
- 新增逐原因处置策略，可独立配置拦截、记录后放行、AI 二审和通知。高风险放行要求 TOTP 与二次确认，超大请求只能临时放行，配置不可用和 AI 异常保持强制拦截。
- 独立统计接口支持时间、分组、用户、模型、客户端、结果和原因筛选；拦截率只统计真正进入审核范围的请求。

## 有界解析与可靠统计

- 指令审核请求体默认上限从 16 MiB 提高到 64 MiB，支持安全配置解析超时和并发内存预算；HTTP 与 WebSocket 共用严格 UTF-8、重复键、结构复杂度和解压后大小限制。
- 正常放行事件先可靠落库，超过保留期后分批归档为小时聚合；时间戳数组按事件编号分片且每行最多 4096 项，聚合数据拥有独立保留期和有界清理。
- 管理页面新增持久化、聚合、过期、统计丢失、审核延迟、AI 延迟和翻译工作器运行指标。

## AI 二审与哈希来源

- 可为有安全文本的摘要不匹配和字段无效事件启用 AI 二审。审核按 `instructions`、`input[1]` 顺序执行，并严格校验结构化输出、置信度、超时、并发和配额。
- AI 通过后，在同一事务中保存事件、AI 来源、加密标准原文及精确下游分组和客户端范围的 24 小时临时哈希；任何事务或服务异常都不会默认放行。
- 哈希库分离摘要身份、加密原文和来源历史，支持人工、AI 和导入来源去重追溯，以及临时规则转永久、禁用和永久撤销。

## 原文审查与按需翻译

- 被拦截、策略放行和 AI 放行事件可保存参与审核字段的加密原文；哈希库可保存产生摘要的加密标准原文。旧数据保持有效并标记为原文不可用。
- 查看、复制、翻译原文及 AI 哈希状态操作均强制管理员 TOTP step-up，并记录独立敏感访问日志。
- 事件和哈希详情新增按需分段翻译，支持简体中文、英文、日文和韩文、内部或外部服务、重试和部分失败；译文只在加密 Redis 中短期保存。

## 前端与运维

- 指令审核页拆分运行配置、原因策略、统计、哈希详情和翻译工作区，补齐 loading、empty、error、disabled 状态及中英文文案。
- 事件列表优先展示可操作结果，保留事件编号、请求 ID、通知状态和一键加入规则集；运行指标使用自适应布局，窄屏不产生页面级横向溢出。
- 运维邮件增加事件编号、原因、最终结果、策略动作、配置版本、字段状态和摘要；邮件仍不包含原文、Bearer Token 或 API Key。

## 数据与兼容性

- 新增迁移 `204` 至 `210`，只扩展指令审核结果、策略、运行配置、哈希来源、AI、翻译、统计聚合、索引、分片和保留元数据。
- 既有事件保持拦截含义，既有规则、哈希、分组、客户端绑定、用户白名单、空字段例外、证据和通知不丢失。
- 升级后的默认行为与 `0.1.170.12` 一致：原因继续拦截，AI 和外部翻译保持关闭。
- 正式发布仍仅构建 `linux/amd64`；测试服验收完成并获得明确批准前，不创建正式标签、Release 或生产更新。
