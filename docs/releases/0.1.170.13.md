# ModelPort 0.1.170.13

本页记录 `0.1.170.13` 正式版本的变更范围和测试服验收结果。逐项验证状态见
[`0.1.170.13-evidence-matrix.md`](./0.1.170.13-evidence-matrix.md)。

## 指令审核结果与原因策略

- 指令审核统一记录 `blocked`、策略放行、AI 放行、哈希放行和例外放行五种最终结果，并保存初始原因、最终原因、策略动作、请求字节数、审核延迟和 AI 延迟。
- 新增逐原因处置策略，可独立配置拦截、记录后放行、AI 二审和通知。高风险放行要求 TOTP 与二次确认，超大请求只能临时放行，配置不可用和 AI 异常保持强制拦截。
- 独立统计接口支持时间、分组、用户、模型、客户端、结果和原因筛选；拦截率只统计真正进入审核范围的请求。

## 有界解析与可靠统计

- 指令审核请求体默认上限从 16 MiB 提高到 64 MiB，支持安全配置解析超时和进程内工作集预算；预算默认 256 MiB，并在数据库、后端和前端统一要求至少为请求体上限的 3 倍。
- HTTP 与 WebSocket 共用严格 UTF-8、重复键、结构复杂度和解压后大小限制。超限请求可先形成审核事件，但 HTTP 最终仍返回 `413`、WebSocket 仍以消息过大关闭；原因策略不能绕过 CDN、Nginx、网关或上游硬限制。
- 正常放行事件先可靠落库，超过保留期后分批归档为小时聚合；时间戳数组按事件编号分片且每行最多 4096 项，聚合数据拥有独立保留期和有界清理。
- 新增兼容迁移，将早期开发候选生成的 `-1` 聚合分片与其后新增分片合并后重新切分，完整保留计数和延迟总量。
- 管理页面新增持久化、聚合、过期、统计丢失、审核延迟、AI 延迟和翻译工作器运行指标；事件写入失败与统计丢失计数持久化到 PostgreSQL，刷新失败会恢复待提交增量并重试。

## AI 二审与哈希来源

- 可为有安全文本的摘要不匹配和字段无效事件启用 AI 二审。审核按 `instructions`、`input[1]` 顺序执行，并严格校验结构化输出、置信度、超时、并发和配额。
- AI 通过后，在同一事务中保存事件、AI 来源、加密标准原文及精确下游分组和客户端范围的 24 小时临时授权；任何事务或服务异常都不会默认放行。
- AI 命中既有人工摘要时复用哈希身份，不修改人工哈希的状态和全局有效期；本次 AI 授权独立绑定当前分组与客户端并按 24 小时到期。
- 哈希库分离摘要身份、加密原文和来源历史；人工创建必须提交标准原文并加密保存，仅显式“摘要导入”允许没有原文；AI 临时授权的来源、状态和有效期下沉到系统规则集关联，支持对单个精确作用域转永久、禁用和永久撤销。
- 系统管理规则集使用专用生命周期，普通规则集保存、删除和分组绑定接口不能修改或扩大 AI 精确作用域。

## 原文审查与按需翻译

- 被拦截、策略放行和 AI 放行事件可保存参与审核字段的加密原文；哈希库可保存产生摘要的加密标准原文。旧数据保持有效并标记为原文不可用。
- 新增独立的敏感内容访问授权。查看、复制、翻译及从事件加入哈希或规则集同时要求真人管理员 JWT、有效敏感授权和 TOTP step-up；Admin API Key 被拒绝。
- 授权持有人可以在 TOTP 保护下授予或撤销其他已启用 TOTP 的有效管理员，系统保护最后一名有效持有人；敏感访问日志关联具体授权 ID、认证方式和授权结果。
- AI 哈希与精确作用域状态操作继续要求 TOTP，但不会借此授予原文读取权限。
- 事件和哈希详情新增按需分段翻译，支持简体中文、英文、日文和韩文、内部或外部服务、重试和部分失败；译文只在加密 Redis 中短期保存。

## 前端与运维

- 指令审核页拆分运行配置、原因策略、统计、哈希详情和翻译工作区，补齐 loading、empty、error、disabled 状态及中英文文案。
- 事件列表优先展示可操作结果，保留事件编号、请求 ID、通知状态和一键加入规则集；运行指标使用自适应布局，窄屏不产生页面级横向溢出。
- 运维邮件增加事件编号、原因、最终结果、策略动作、配置版本、字段状态和摘要；邮件仍不包含原文、Bearer Token 或 API Key。
- 审核事件和通知 outbox 意图在同一数据库事务内提交；AI 流程还会原子提交 AI 审核、哈希、精确作用域和来源。通知状态新增 `enqueue_failed`，并与 `no_recipient` 和 SMTP `failed` 明确区分。

## 数据与兼容性

- 新增迁移 `204` 至 `216`，只扩展指令审核结果、策略、运行配置、哈希来源、AI、翻译、统计聚合、索引、分片、敏感授权、通知状态、工作集预算和运行计数。
- `211` 重分片遗留聚合，`212` 分离 AI 哈希身份与精确作用域生命周期，`213` 建立敏感授权及访问关联，`214` 增加通知意图准备失败状态，`215` 把旧工作集预算提升到至少 3 倍，`216` 持久化运行计数并收敛旧原文状态。
- 既有事件保持拦截含义，既有规则、哈希、分组、客户端绑定、用户白名单、空字段例外、证据和通知不丢失。
- 升级后的默认行为与 `0.1.170.12` 一致：原因继续拦截，AI 和外部翻译保持关闭。
- 正式发布仅构建 `linux/amd64`；本次发布只推送源码、GitHub Release 和 GHCR 镜像，不自动更新测试服或生产服务器。

## 验证状态

- Go 全量、指令审核 race、真实 PostgreSQL 集成与迁移测试，以及前端 1607 项 Vitest、TypeScript、ESLint 和生产构建均通过。
- AMD64 候选 `0.1.170.13-dev.3` 已部署测试服；两次 `--migrate-only` 后迁移数稳定为 269，核心 HTTP、SSE、compact、WebSocket、42/65 MiB、AI 故障关闭和通知限流路径符合预期。
- 四个桌面与移动视口的深浅色页面均无横向溢出；验收临时数据已清理，业务数量和规则集恢复到升级前备份状态。
- 外部 AI、翻译、SMTP 和 TOTP 依赖具体部署配置，正式启用前仍需在目标环境完成对应服务验收。
- 正式 AMD64 镜像发布为 `ghcr.io/abingooo/modelport:custom-v0.1.170.13`，并同时生成绑定发布提交的不可变 `sha-<commit>` 标签。
