# ModelPort 0.1.170.14

## 指令审核 V2

- 指令审核运行链路完成源码级重构，只校验 Responses 请求的顶层 `instructions` 和 `input[1]`，不再携带 V1 的逐原因策略、翻译及聚合工作区进入热路径。
- 哈希统一使用解析后原文的 UTF-8 字节计算 SHA-256，不裁剪、不改写、不区分字段来源；任一字段命中同一审核范围内的可信哈希即可放行。
- 审核范围由认证后的下游分组和客户端规则共同确定，模型仅作为事件元数据，不参与范围匹配。内置 Codex、OpenCode、可信内部、其他和未知客户端，并支持管理员添加前缀或 RE2 规则。
- 用户白名单和两个字段均为空的请求保留例外放行；未进入有效分组及客户端范围的请求不触发 V2。

## 运行模式与 AI 二审

- 新增 `off`、`observe`、`enforce` 三种模式。观察模式异步执行 AI 并立即放行，强制模式同步执行多节点故障转移，AI 异常、超时、无明确结论或持久化失败均不会默认放行。
- AI 先审核 `instructions`，未通过时继续审核 `input[1]`；通过后原子保存事件、审核来源、加密原文和仅绑定当前分组及客户端范围的候选哈希。
- AI 节点支持优先级、独立超时、独立并发和加密 API Key。默认全局并发为 64、单节点并发为 16，并提供队列等待、总超时、缓存和候选保留期配置。
- 启用观察或强制模式前必须同时具备有效审核范围、可用 AI 节点和原文加密能力；运行配置使用版本号进行并发更新保护。

## 证据与安全边界

- 被拦截事件保存事件编号、请求 ID、下游用户及 API Key、分组、客户端、模型、字段状态、完整摘要、审核延迟和通知状态，不在普通接口、日志、错误响应或邮件中暴露原文和凭据。
- 原文使用现有敏感数据密钥加密保存。默认 4 MiB 内保存完整字段，较大字段只保存有界样本，同时保留完整内容摘要和字节数；请求本身继续受 HTTP 与 WebSocket 网关的 256 MiB 上限约束。
- 查看、复制和从事件一键加入可信指令继续要求真人管理员 JWT、敏感内容授权和 TOTP step-up，并生成独立访问审计记录。
- 拦截响应固定为通用 `403 request_rejected`，不包含 `instructions`、`input[1]`、哈希或白名单等实现信息；用户和运维通知通过持久化 outbox 异步发送。

## 管理界面

- 指令审核页面精简为审核日志、可信指令、审核范围和 AI 设置四个工作区，顶部独立展示审核量、拦截、哈希放行、AI 放行、例外放行和拦截率。
- 日志支持请求、事件编号、用户、分组、客户端、模型、结果、原因和时间筛选，可查看加密证据、批量删除事件并一键加入可信指令。
- 可信指令支持加密原文、作用域、来源和状态管理；审核范围支持分组、客户端规则和用户白名单；AI 设置集中管理模式、限流、超时、保留期和节点故障转移。
- 页面改为全宽自适应布局，修正 1024px 页头操作区挤压；1440px、1024px 和 390px 视口均无页面级横向溢出。

## 数据与兼容性

- 新增迁移 `217_instruction_audit_v2.sql`，建立独立 V2 配置、AI 节点、客户端、范围、白名单、哈希、事件、加密证据、AI 审核和敏感访问表，并扩展统一安全通知来源。
- 升级时保留 V1 的全部表和历史数据以便回滚，但关闭 V1 运行开关；V2 不自动继承旧规则，首次升级固定以空规则和 `off` 模式启动，避免未经复核的策略直接生效。
- 本次迁移不修改用户、余额、API Key、账号、分组、订阅、用量或计费数据；迁移可重复执行，测试数据库从 269 条稳定升级到 270 条。
