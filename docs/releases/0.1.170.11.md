# ModelPort 0.1.170.11

## 定时抽奖人满开奖

- 定时开奖活动新增可选的“人满开奖”模式。管理员可独立设置满员人数；达到人数后提前封闭参与入口并立即触发开奖，未满员时仍按原定开奖时间执行。
- 满员人数按独立用户统计，同一用户的多次参与只占一个人数名额，但每条参与记录仍分别参与开奖。管理端和用户端同时展示独立人数、人次与满员进度，避免统计口径混淆。
- 达到阈值的参与事务会持久化满员状态并严格拒绝第 N+1 名参与者；重复提交仍按原幂等键返回已有记录，不会重复占位或派奖。

## 开奖可靠性

- 满员后会立即唤醒后台开奖任务；持久化满员状态同时纳入原有 30 秒扫描，即使应用在触发瞬间重启或单次派奖失败，也会自动重试而不会重新开放参与入口。
- 满员开奖继续使用活动行锁、奖品库存锁、唯一开奖记录和事务派奖，避免并发重复开奖、超发余额或重复生成订阅兑换码。
- 开奖审计事件新增触发来源，可区分满员开奖、定时开奖和管理员手动开奖。满员活动派奖完成后进入原有完成状态，不再显示“正在开奖”。

## 数据与发布

- 新增迁移 `202_lottery_full_draw.sql`，只为抽奖活动增加可空的满员人数、满员时间及查询索引；现有活动默认关闭人满开奖，不修改用户、API Key、余额、订阅、兑换码、既有参与记录或历史派奖结果。
- 正式镜像仅发布 `linux/amd64`，标签为 `ghcr.io/abingooo/modelport:custom-v0.1.170.11`；发布工作流只创建 GitHub Release 和 GHCR 镜像，不自动部署生产环境。
