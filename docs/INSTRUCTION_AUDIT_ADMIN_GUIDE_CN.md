# ModelPort 指令审核管理员指南

本文适用于 ModelPort `0.1.170.13`。架构与安全不变量见
[`INSTRUCTION_AUDIT_ARCHITECTURE_CN.md`](./INSTRUCTION_AUDIT_ARCHITECTURE_CN.md)，发布验收证据见
[`0.1.170.13-evidence-matrix.md`](./releases/0.1.170.13-evidence-matrix.md)。

## 上线前检查

1. 备份 PostgreSQL、Redis 持久化数据、应用配置和固定加密密钥。
2. 确认所有实例使用同一个固定 `TOTP_ENCRYPTION_KEY`，格式为 64 位十六进制值。更换或丢失该密钥会导致既有证据、哈希原文和已保存服务凭据无法解密。
3. 确认 Redis 可用。配置失效通知、AI 配额和翻译结果依赖 Redis。
4. 将 CDN、Nginx、`SERVER_MAX_REQUEST_BODY_SIZE`、`GATEWAY_MAX_BODY_SIZE` 和 WebSocket 帧上限逐层核对。希望由应用记录超限事件时，外层上限必须高于指令审核上限；默认 64 MiB 时可沿用仓库基线的 256 MiB 外层硬限制。
5. 确认至少一名有效管理员已启用 TOTP，并在“敏感内容访问授权”中显示为有效持有人。普通管理员身份不自动获得原文读取权限。
6. 确认运行配置中的工作集预算至少是请求体上限的 3 倍。默认 64 MiB 请求体和 256 MiB 预算为 4 倍；若计划降低到 192 MiB，必须先完成满尺寸 HTTP、WebSocket 和并发压测。
7. 在数据库副本依次执行迁移 `204-216` 两次，第二次不得产生额外结构或数据变化，并核对升级前后的事件、哈希、规则、证据、通知、访问审计和运行计数器数量。

## 推荐启用顺序

1. 在“系统设置 -> 功能开关 -> 风控中心”保持指令审核总开关关闭。
2. 进入“安全审计 -> 指令审核 -> 运行配置”，确认请求体、解析预算和保留期。
3. 在哈希库使用标准原文创建人工哈希；只有迁移或互操作场景才使用“摘要导入”。
4. 创建规则集并关联哈希；按需配置严格空字段例外和用户白名单。
5. 将规则集绑定到下游分组，选择全部客户端或明确的客户端集合。
6. 检查“规则有效分组”与预期一致，至少存在一个有效绑定。
7. 检查所有原因策略。升级后的默认动作均应维持与旧版一致的拦截行为。
8. 打开总开关，先使用测试 API Key 验证命中、未命中和通知，再逐步扩大分组范围。

## 运行配置

### 解析和保留

- 请求体上限默认 64 MiB，可设置 1-128 MiB。
- 解析超时默认 500 ms，可设置 50-5000 ms。
- 进程内请求体工作集预算默认 256 MiB，数据库、后端和前端均要求不低于请求体上限的 3 倍，最大 2 GiB。
- 正常放行事件默认保留 7 天，随后归档到小时聚合。
- 聚合统计默认保留 365 天；到期清理会永久减少可查询的历史统计范围。
- 哈希原文保留期控制标准原文密文，到期只删除密文，不停用摘要。
- 页面顶部的证据保留期控制事件人工审查证据，与哈希原文保留期相互独立。

修改运行配置时使用页面当前 `config_version`。若其他管理员已经修改配置，页面会要求刷新后重试，不能覆盖新版本。

HTTP、WebSocket 帧读取和严格解析共享该进程内预算。预算不足时请求会等待到解析截止时间，而不是无限排队；生产值应按“单请求上限 x 预期同时处理的大请求数 x 工作集系数”评估，不能把 3 倍数据库下限当作容量规划结论。

### 64 MiB 与硬上限

- 页面“审核上限”是指令审核读取与解析边界，默认 64 MiB。
- 页面“HTTP/WebSocket 有效上限”取审核值与对应网关值的较小者；CDN、Nginx 和上游限制不在应用内自动探测，仍需人工核对。
- 请求刚超过审核边界但尚未被外层拒绝时，应用会尽量先记录 `request_too_large`；HTTP 随后返回 `413`，WebSocket 随后以消息过大关闭。
- CDN 或 Nginx 先返回 `413` 时，ModelPort 没有收到请求，不会生成指令审核事件。
- `request_too_large` 配置为“忽略并记录”只改变指令审核事件结果，不能绕过 CDN、Nginx、全局 HTTP、网关、WebSocket 或上游硬限制，也不能转发未完整读取的请求。

### 原因策略

| 动作 | 行为 |
| --- | --- |
| 拦截 | 返回通用 403、保存事件，并根据告警开关异步通知 |
| 忽略并放行 | 保存完整事件后继续其他网关链路，不绕过鉴权、风控、限流、计费和上游限制 |

建议只在短期故障排查时使用“忽略并放行”。高风险原因要求 TOTP 和二次确认；超大请求还必须设置 24 小时内的截止时间。`config_unavailable` 和 `ai_error` 不能改为放行。对于 `request_too_large`，该动作不会改变上一节说明的传输层最终拒绝。

“发送通知”只控制对应最终原因的通知：

- 拦截：用户收到简洁安全提醒，运维收到可定位事件的元数据。
- 策略放行：默认只通知运维，避免向用户发送错误的违规通知。
- 事件与通知意图在同一数据库事务提交；AI 结果还会把 AI 审核、临时作用域、来源和通知意图纳入同一事务。
- 邮件发送失败不改变请求结果，可在事件中查看等待、处理中、重试、已发送、失败、抑制、无收件人或意图准备失败状态。

状态含义：`no_recipient` 表示配置中没有有效收件人，`enqueue_failed` 表示收件人查询或通知意图准备失败，`failed` 才表示 SMTP 发送重试耗尽。三者不能合并解释。

## 敏感内容访问授权

原文权限是独立于管理员角色的第二层授权。受保护操作必须同时满足：

1. 使用真人管理员 JWT 会话；Admin API Key 不允许访问。
2. 当前管理员拥有未撤销的“指令敏感内容”授权，且账号仍为有效管理员。
3. 当前操作完成 TOTP step-up。

进入指令审核页后先查看“敏感内容访问授权”状态。只有现有授权持有人可以加载授权列表、给其他管理员授权或撤销授权；目标管理员必须处于有效状态并已启用 TOTP。系统拒绝撤销最后一名有效持有人，防止网页端失去恢复路径。

迁移 `213` 在授权表为空时只为最早创建的有效管理员建立一次 `migration_bootstrap` 授权。若该账号不可用，应先通过受控运维流程恢复持有人，不能通过数据库随意复制授权记录。授权和撤销应填写原因；授权历史、认证方式及访问结果均会保留。

需要“授权 + TOTP”的操作包括：查看原文、记录复制、创建或读取翻译任务，以及把事件原文加入候选哈希或规则集。只修改原因策略、运行配置、普通哈希元数据或 AI 精确作用域状态的操作仍要求 TOTP，但不会因此获得原文读取能力。撤销授权后，前端会清除已加载原文和译文，后端也会重新核对授权；翻译任务不能凭创建时的旧授权继续解密结果。

## 哈希、规则集和范围

### 新增哈希

- 手工录入：必须提交标准原文。后端使用不裁剪、不改空格、不改换行、不做 Unicode 归一化的 `identity_utf8_v1` 规则生成摘要，并加密保存同一份 UTF-8 字节；来源记为 `manual`。
- 摘要导入：只用于迁移或无法取得标准原文的互操作场景，输入 64 位十六进制 SHA-256，来源记为 `import`，原文状态为 `raw_content_unavailable`。摘要导入不能伪装成人工原文记录。
- `instructions` 和 `input[1]` 可以使用同一个摘要；字段来源用于追溯，不改变精确字节摘要的身份。
- 手工、导入和 AI 来源分别保存，不会因摘要去重而覆盖历史来源。

### 规则集

一个请求命中任意启用规则集中的有效条件即可放行。多个规则集采用并集语义。

- “两个字段均为空时放行”只接受结构合法的精确空值，不接受空格、`null`、错误类型或非法 JSON。
- 用户白名单按稳定用户 ID 保存，只在已经命中分组和客户端审核范围后生效。
- 系统管理规则集由 AI 精确范围自动维护，不应作为普通多分组规则使用，也不能通过普通规则集或分组绑定接口编辑、删除或扩展。

### 分组与客户端绑定

- 分组必须是认证后的下游 API Key 分组。
- 选择“全部客户端”保持仅按分组覆盖。
- 选择指定客户端时，只审核匹配的 Codex VS Code、Codex CLI、Codex Desktop、OpenCode、可信内部调用、其他或未知客户端。
- 普通 User-Agent 不能伪造 `modelport_internal`。
- 模型只作为日志和统计筛选元数据，不限制审核范围。

## AI 二次审核

AI 默认关闭。启用前配置专用 OpenAI 兼容 Base URL、模型、Token、超时、并发、最低置信度、单用户 RPM、单用户每日加库、全局每日加库和提示词版本。

推荐顺序：

1. 使用独立、低权限和可审计的上游凭据，不要复用下游用户 Key。
2. 保持 AI 总开关关闭，保存并验证配置。
3. 先只为测试分组绑定的 `hash_mismatch` 开启 AI。
4. 打开 AI 总开关，验证 pass、reject、uncertain、超时和格式错误。
5. 观察 AI 延迟、错误和每日配额，再决定是否扩大范围。

AI 通过会创建或复用哈希身份，并在 `ai:<group_id>:<client_type>` 系统规则集中创建仅适用于当前 `(下游分组, 检测客户端)` 的 24 小时临时关联。有效期属于该精确关联，不属于哈希全局身份；因此复用人工哈希不会缩短或扩大人工规则的有效范围。管理员应在到期前查看来源、标准原文、模型、提示词版本、置信度和理由，然后对具体关联选择：

- 转为永久：把该关联来源转为人工、保持 active 并清除到期时间。
- 禁用：只停止该精确关联匹配并保留追溯数据。
- 永久撤销：永久撤销该精确关联，不可重新启用。

不要用普通规则集保存、删除或分组绑定接口操作系统规则集；这些接口会返回冲突。若需要在其他分组或客户端永久放行，应建立普通规则集并显式配置范围，而不是修改系统规则集的 `system_key` 或绑定。

AI 异常、超时、配额不足、低置信度或事务失败都不会默认放行。

## 按需翻译

翻译总开关默认关闭。内部翻译复用已配置的 AI 服务；外部翻译需单独开启并配置 Base URL、模型和 Token。

1. 确认当前管理员拥有敏感内容授权，在事件证据或哈希详情中完成 TOTP 验证并查看加密原文。
2. 选择目标语言，默认简体中文。
3. 选择内部或外部服务并点击“一键翻译”。
4. 页面显示分段进度；可重试任务会保持处理中，成功、部分失败和最终失败分别展示。
5. 原文和译文并排显示，译文不覆盖原文、不改变摘要和审核结论。

译文只在加密 Redis 中按 TTL 短期保存。普通日志不会记录原文或译文。外部翻译前会脱敏明显的 Bearer Token、API Key、令牌和邮箱，但管理员仍应只使用受信任服务。创建任务时会记录授权 ID；授权被撤销后，旧页面或旧任务 ID 不能继续取得敏感结果。

## 日志和统计

审核日志默认优先展示拦截、策略放行和 AI 结果，也可筛选所有结果。可按事件编号、统一搜索、时间、分组、用户、模型、客户端、最终结果、原因、字段结果和通知状态定位。

事件详情提供：

- 事件编号、请求 ID、下游用户、API Key、分组、客户端、模型和端点。
- 初始原因、最终原因、策略动作、最终结果、配置版本和请求字节数。
- `instructions`、`input[1]` 的存在状态、结果和 SHA-256。
- 审核延迟、AI 延迟、证据状态、AI 来源和通知状态。
- 经 TOTP 保护的加密原文查看、复制、翻译和一键加入规则集。

顶部统计与当前时间、分组、用户、模型、客户端、结果和原因筛选同步。统计接口不使用事件编号、全文搜索、字段结果或通知状态，因此这些事件专用筛选不会错误影响统计。

## 维护与故障处理

### 配置加载失败

页面显示加载失败时，实例继续使用最近一次有效快照。不要通过重启掩盖问题；先检查 PostgreSQL、Redis 失效消息和配置版本。若已纳入范围的分组无法取得有效配置，系统默认拒绝。

### 持久化或统计丢失

“写入失败”或“统计丢失”大于零时，检查数据库连接、锁等待、磁盘空间和服务日志。两个计数会周期性写入 PostgreSQL，写入失败时保留待提交增量并重试，进程重启后仍可读取已落库累计值。不得仅依据页面列表为空判断请求没有被审核，也不能把待提交计数当成已经持久化成功。

### 翻译积压

检查 Redis、翻译服务、工作器活跃数、重试任务和外部服务限流。删除翻译任务不会改变历史审核结论。

### 清理数据

- 事件列表支持单条、当前页批量和按筛选快照清理。
- 删除事件会级联清理事件证据和关联通知，但 AI 来源中的事件引用会保留为空，哈希仍可追溯到 AI 审核记录。
- 删除哈希前必须先解除规则集引用。
- 删除规则集前必须先解除分组绑定。
- 系统管理规则集不允许通过普通删除流程处理；只能管理其中的精确 AI 作用域关联。
- 正常放行事件和聚合数据由后台保留策略分批维护，不应直接手工删除表数据。

### 通知异常

- `no_recipient`：检查用户邮箱或运维监控收件人配置。
- `enqueue_failed`：检查收件人查询、通知模板准备和相关服务依赖；此状态已经与事件一起持久化。
- `retry`：后台工作器将再次尝试发送。
- `failed`：SMTP 或邮件服务错误已经达到最大尝试次数，需要人工处理。
- `suppressed`：相同通知被去重或频率策略抑制，不代表发送失败。

## 测试服验收清单

- 哈希命中、策略放行、AI 放行、用户白名单和空字段例外均形成正确结果。
- 未绑定分组保持不适用；绑定但配置失效的分组默认拒绝。
- HTTP、SSE 和 WebSocket 使用相同规则；compact 端点保持排除。
- 分别验证 1、16、32、42、64、65 MiB；默认配置下 42 MiB 合法请求应完成审核，65 MiB 应形成 `request_too_large`，随后由 HTTP/WS 硬限制终止。
- 分别验证默认 256 MiB 工作集预算和允许的最低 3 倍配置；记录 HTTP、WebSocket、并发等待、超时和进程内存结果。
- AI 错误、翻译错误和邮件错误均不会造成意外放行或阻塞正常返回。
- 原文查看、复制、翻译和事件加库同时要求敏感授权与 TOTP；AI 作用域状态操作要求 TOTP；两类操作均应留下对应审计。
- 统计总数满足五种最终结果之和，筛选后列表和统计口径一致。
- 页面在桌面、窄屏、深色和浅色模式下无页面级横向溢出。
