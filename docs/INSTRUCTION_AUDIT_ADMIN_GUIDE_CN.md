# ModelPort 指令审核管理员指南

本文适用于 ModelPort `0.1.170.13`。架构与安全不变量见
[`INSTRUCTION_AUDIT_ARCHITECTURE_CN.md`](./INSTRUCTION_AUDIT_ARCHITECTURE_CN.md)。

## 上线前检查

1. 备份 PostgreSQL、Redis 持久化数据、应用配置和固定加密密钥。
2. 确认所有实例使用同一个固定 `TOTP_ENCRYPTION_KEY`，格式为 64 位十六进制值。更换或丢失该密钥会导致既有证据、哈希原文和已保存服务凭据无法解密。
3. 确认 Redis 可用。配置失效通知、AI 配额和翻译结果依赖 Redis。
4. 将 Nginx 或 CDN 请求体上限设置为高于指令审核配置。默认 64 MiB 时建议边缘使用 100 MiB，并保留独立硬上限。
5. 确认管理员已经启用 TOTP；敏感读取和所有配置变更都要求 step-up。
6. 在数据库副本执行两次迁移，第二次不得产生额外结构或数据变化。

## 推荐启用顺序

1. 在“系统设置 -> 功能开关 -> 风控中心”保持指令审核总开关关闭。
2. 进入“安全审计 -> 指令审核 -> 运行配置”，确认请求体、解析预算和保留期。
3. 在哈希库创建人工哈希，或输入标准原文由浏览器按精确 UTF-8 字节计算摘要。
4. 创建规则集并关联哈希；按需配置严格空字段例外和用户白名单。
5. 将规则集绑定到下游分组，选择全部客户端或明确的客户端集合。
6. 检查“规则有效分组”与预期一致，至少存在一个有效绑定。
7. 检查所有原因策略。升级后的默认动作均应维持与旧版一致的拦截行为。
8. 打开总开关，先使用测试 API Key 验证命中、未命中和通知，再逐步扩大分组范围。

## 运行配置

### 解析和保留

- 请求体上限默认 64 MiB，可设置 1-128 MiB。
- 解析超时默认 500 ms，可设置 50-5000 ms。
- 并发解析预算默认 256 MiB，必须不低于单请求上限。
- 正常放行事件默认保留 7 天，随后归档到小时聚合。
- 聚合统计默认保留 365 天；到期清理会永久减少可查询的历史统计范围。
- 哈希原文保留期控制标准原文密文，到期只删除密文，不停用摘要。
- 页面顶部的证据保留期控制事件人工审查证据，与哈希原文保留期相互独立。

修改运行配置时使用页面当前 `config_version`。若其他管理员已经修改配置，页面会要求刷新后重试，不能覆盖新版本。

### 原因策略

| 动作 | 行为 |
| --- | --- |
| 拦截 | 返回通用 403、保存事件，并根据告警开关异步通知 |
| 忽略并放行 | 保存完整事件后继续其他网关链路，不绕过鉴权、风控、限流、计费和上游限制 |

建议只在短期故障排查时使用“忽略并放行”。高风险原因要求 TOTP 和二次确认；超大请求还必须设置 24 小时内的截止时间。`config_unavailable` 和 `ai_error` 不能改为放行。

“发送通知”只控制对应最终原因的通知：

- 拦截：用户收到简洁安全提醒，运维收到可定位事件的元数据。
- 策略放行：默认只通知运维，避免向用户发送错误的违规通知。
- 邮件发送失败不改变请求结果，可在事件中查看等待、重试、已发送、失败、抑制或无收件人状态。

## 哈希、规则集和范围

### 新增哈希

- 已知摘要：输入 64 位小写或大写十六进制 SHA-256。
- 已知标准原文：切换到原文模式，系统使用不裁剪、不改空格、不改换行、不做 Unicode 归一化的 `identity_utf8_v1` 规则生成摘要并加密保存原文。
- `instructions` 和 `input[1]` 可以使用同一个摘要；字段来源用于追溯，不改变精确字节摘要的身份。
- 手工、导入和 AI 来源分别保存，不会因摘要去重而覆盖历史来源。

### 规则集

一个请求命中任意启用规则集中的有效条件即可放行。多个规则集采用并集语义。

- “两个字段均为空时放行”只接受结构合法的精确空值，不接受空格、`null`、错误类型或非法 JSON。
- 用户白名单按稳定用户 ID 保存，只在已经命中分组和客户端审核范围后生效。
- 系统管理规则集由 AI 精确范围自动维护，不应作为普通多分组规则使用。

### 分组与客户端绑定

- 分组必须是认证后的下游 API Key 分组。
- 选择“全部客户端”保持仅按分组覆盖。
- 选择指定客户端时，只审核匹配的 Codex VS Code、Codex CLI、Codex Desktop、OpenCode、可信内部调用、其他或未知客户端。
- 普通 User-Agent 不能伪造 `modelport_internal`。
- 模型只作为日志和统计筛选元数据，不限制审核范围。

## AI 二次审核

AI 默认关闭。启用前配置专用 OpenAI 兼容 Base URL、模型、Token、超时、并发、最低置信度、单用户 RPM、单用户每日加库、全局每日加库和提示词版本。

推荐顺序：

1. 使用独立、低权限和可审计的上游凭据，不要复用下游用户 Key。
2. 保持 AI 总开关关闭，保存并验证配置。
3. 先只为测试分组绑定的 `hash_mismatch` 开启 AI。
4. 打开 AI 总开关，验证 pass、reject、uncertain、超时和格式错误。
5. 观察 AI 延迟、错误和每日配额，再决定是否扩大范围。

AI 通过会创建仅适用于当前 `(下游分组, 检测客户端)` 的 24 小时临时哈希。管理员应在到期前查看来源、标准原文、模型、提示词版本、置信度和理由，然后选择：

- 转为永久：保持 active 并清除到期时间。
- 禁用：停止匹配但保留追溯数据。
- 永久撤销：不可重新启用。

AI 异常、超时、配额不足、低置信度或事务失败都不会默认放行。

## 按需翻译

翻译总开关默认关闭。内部翻译复用已配置的 AI 服务；外部翻译需单独开启并配置 Base URL、模型和 Token。

1. 在事件证据或哈希详情中完成 TOTP 验证并查看加密原文。
2. 选择目标语言，默认简体中文。
3. 选择内部或外部服务并点击“一键翻译”。
4. 页面显示分段进度；可重试任务会保持处理中，成功、部分失败和最终失败分别展示。
5. 原文和译文并排显示，译文不覆盖原文、不改变摘要和审核结论。

译文只在加密 Redis 中按 TTL 短期保存。普通日志不会记录原文或译文。外部翻译前会脱敏明显的 Bearer Token、API Key、令牌和邮箱，但管理员仍应只使用受信任服务。

## 日志和统计

审核日志默认优先展示拦截、策略放行和 AI 结果，也可筛选所有结果。可按事件编号、统一搜索、时间、分组、用户、模型、客户端、最终结果、原因、字段结果和通知状态定位。

事件详情提供：

- 事件编号、请求 ID、下游用户、API Key、分组、客户端、模型和端点。
- 初始原因、最终原因、策略动作、最终结果、配置版本和请求字节数。
- `instructions`、`input[1]` 的存在状态、结果和 SHA-256。
- 审核延迟、AI 延迟、证据状态、AI 来源和通知状态。
- 经 TOTP 保护的加密原文查看、复制、翻译和一键加入规则集。

顶部统计与当前时间、分组、用户、模型、客户端、结果和原因筛选同步。统计接口不使用事件编号、全文搜索、字段结果或通知状态，因此这些事件专用筛选不会错误影响统计。

## 维护与故障处理

### 配置加载失败

页面显示加载失败时，实例继续使用最近一次有效快照。不要通过重启掩盖问题；先检查 PostgreSQL、Redis 失效消息和配置版本。若已纳入范围的分组无法取得有效配置，系统默认拒绝。

### 持久化或统计丢失

“写入失败”或“统计丢失”大于零时，检查数据库连接、锁等待、磁盘空间和服务日志。不得仅依据页面列表为空判断请求没有被审核。

### 翻译积压

检查 Redis、翻译服务、工作器活跃数、重试任务和外部服务限流。删除翻译任务不会改变历史审核结论。

### 清理数据

- 事件列表支持单条、当前页批量和按筛选快照清理。
- 删除事件会级联清理事件证据和关联通知，但 AI 来源中的事件引用会保留为空，哈希仍可追溯到 AI 审核记录。
- 删除哈希前必须先解除规则集引用。
- 删除规则集前必须先解除分组绑定。
- 正常放行事件和聚合数据由后台保留策略分批维护，不应直接手工删除表数据。

## 测试服验收清单

- 哈希命中、策略放行、AI 放行、用户白名单和空字段例外均形成正确结果。
- 未绑定分组保持不适用；绑定但配置失效的分组默认拒绝。
- HTTP、SSE 和 WebSocket 使用相同规则；compact 端点保持排除。
- 默认配置下 42 MiB 合法请求完成审核，65 MiB 请求形成 `request_too_large`。
- AI 错误、翻译错误和邮件错误均不会造成意外放行或阻塞正常返回。
- 原文查看、复制、翻译和哈希状态操作均要求 TOTP 并留下访问审计。
- 统计总数满足五种最终结果之和，筛选后列表和统计口径一致。
- 页面在桌面、窄屏、深色和浅色模式下无页面级横向溢出。
