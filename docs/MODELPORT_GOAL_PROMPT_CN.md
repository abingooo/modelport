- Prompt Audit 与 Instruction Audit V2 应正确协作：先根据当前代码的实际 gateway 路由和 payload 建立可审计清单，扫描必须覆盖 `GET`、`POST`、`PUT`、`PATCH`、`DELETE` 和 WebSocket 注册，不能只扫描 `POST`。Prompt Audit 覆盖清单中所有确实包含用户文本的入口（至少核对 Chat、Responses、Messages、Embeddings、搜索、图片、视频、音频及其 HTTP、SSE、WebSocket 链路）；控制面、无用户文本或仅传输/令牌化的路由必须逐项列为 `excluded` 并写明理由，不能凭路径名称猜测。Instruction Audit V2 的硬范围仅为清单明确标记的规范 Responses 生成入口（`/responses` 及合法别名、HTTP/SSE、Responses WebSocket 的 `response.create` 轮次）中的 `instructions` 与 `input[1]` 指令字段，明确排除 `/responses/compact`、`/responses/input_tokens`、`/live`/WebRTC、Chat、Messages，以及原生 Grok `/realtime` 音频帧；这些入口是否属于 Prompt Audit，仍按是否存在可审计文本在清单中单独判定。不得仅因复用了 `openai_responses` 协议字符串就触发 V2。每个入口都必须列出并实际运行路由级覆盖测试；同一请求或 WebSocket 轮次中两条链各最多执行一次，任一链放行都不能绕过另一条。若业务要扩大上述 V2 范围，必须先报告并获得明确批准，同时新增字段提取、错误语义和路由测试。
